# 属性候选的进程内生成与封存

固定游戏构建 25480438、HellForge SDK 13。`mod/src/ep_property_image.*` 现在直接在 C++ 内生成两份经过回溯适配的映像；`ep_property_code.*` 把它连接到会话代码所有者。研究 Mod 初始化仍不调用它，不会自动发布 hook。

## 已实现的范围

| 候选 | 代码 | 完整映像 | 位址重定位 | 回溯表偏移 |
|---|---:|---:|---:|---:|
| 属性发送 | 670 bytes | 708 bytes | 8 处 | 696 |
| 属性接收 | 398 bytes | 436 bytes | 5 处 | 424 |

输入为明确提供的五个数值：游戏映像基址、候选代码地址、名册地址、属性存储地址、拒绝分支地址。纯生成接口只处理这些数值，不解引用它们；不扫描模块、进程或可用地址。绝对名册及属性地址以 64 位写入，游戏全局、调用和拒绝出口使用有符号 rel32。内部相对分支随整份映像平移，不另行改变。

`ep_property_templates.h` 的可变字段先置零，所有修补位置由固定候选的完整反汇编提取。生成工具拒绝未知外部引用、未知绝对立即数或数量变化；模板同时记录源生成器与原始 unwind 来源锁的指纹。既有 Python 生成器继续强制验证保存的代码与五段原始回溯资料。普通源码构建和引擎测试都会重新生成并逐字节核对模板，默认不写回；只有显式 `--write` 更新它。生产 Mod 的执行不依赖 Python、Capstone 或文件读取。

数值检查保持既有生成器的要求：正数、对齐、低 canonical 范围、属性偏置不得下溢、已知区间不得重叠，以及新旧两阶段的 rel32 范围。重叠检查包含完整映像末尾的 unwind 与函数表，不能只检查可执行指令部分。保留旧阶段的相对范围约束，使原生版不会悄悄接受参考生成器拒绝的位置。发散或范围错误不会留下部分输出。

这些是固定源码及数值的检查，**不是当前游戏映像、地址可读性或资源生命期证明**。动态原始代码识别与有效异常表仍未验证。

## 与会话所有者连接

`ep_property_code_prepare` 执行以下步骤：

1. 为相应候选分配 708 或 436 字节 RW 存储。`code_address=0` 由 Windows 选择，否则要求精确地址；不进行邻近地址搜索。
2. 使用分配实际返回的基址生成映像。地址不合适时拒绝，例如外部引用超出 rel32 距离。
3. 调用既有 `seal`，封为 RX、刷新缓存、登记函数表，返回 READY 所有权句柄。此时仍可取消，且没有调用 SDK hook。
4. 生成或封存失败时取消尚未发布的配置。如果取消本身失败，返回 `EP_PROPERTY_CLEANUP` 并保留句柄及最新状态；调用方须重试 `ep_session_code_discard`，不能遗失记录或继续宣称准备成功。

新接口采用 `EP_PROPERTY_OK=0`，其余为错误码；既有 `ep_session_code_*` 仍为成功 1。两者不要混用。`EpPropertyImage` 同时返回代码长度、完整长度和元数据偏移。模板是编译时固定资料，接口不接收外部任意模板。

两个候选仍须作为更大容量事务的一部分共同启用。这个准备函数不提供发布、撤销已发布 hook、外部数据所有权、拒绝处理函数或原生角色创建。已发布代码的会话保留规则见 [SESSION_CODE.zh-CN.md](SESSION_CODE.zh-CN.md)。每幅映像远低于所有者的 65,536 bytes 分配上限；这个分配上限与历史游戏读取预算无关，没有新增游戏采样。

## 验证与重建

`evidence/property-image-validation.json` 保存独立验证及源码/测试 DLL 指纹：

- 538 组有效输入的完整映像与原 Python 参考逐字节一致，包含高位地址、两份存储独立变动和合法边界。
- 132 组无效输入在两种实现中均拒绝；包含相对范围两端及其外一字节、对齐错误、整数范围和元数据尾部重叠。失败输出完整清零。
- 4 项无效 API 参数检查。
- 50 项自有进程所有权检查：精确地址与系统分配地址、实际映像比对、RX 权限、Windows 表查找与撤销、正常释放、生成失败清理、封存失败清理、释放失败保留句柄及重试。SDK hook 调用次数为零。

测试 DLL 只为本地验证导出入口，生产 Mod 不导出测试接口。实际属性函数体只在 Unicorn 内执行；Windows 测试仅复制、登记和查找这些映像，不原生调用游戏代码。所有外部输入地址都是合成数值。

八端 `native_roster_sync.py` 现在明确加载这次编译的测试 DLL，以生产 C++ 生成器产生的代码执行 8 次发送和 56 次接收。每幅映像先与参考比较，再把原生生成的字节交给模拟器。1,678 次消费者断言和包含基线的 264 次后端检查保持通过；封包器及实体分派仍为测试桥接，详见 [NATIVE_SYNC.zh-CN.md](NATIVE_SYNC.zh-CN.md)。

完整复现使用 [引擎构建命令](engine/README.zh-CN.md#重建与证据)。它编译 `property_image_test.dll`、运行差分与生命周期验证，然后执行八端链路并交叉记录收据指纹。只核对模板可运行：

```powershell
py -3.12 -B hellforge_multiplayer/tools/generate_property_templates.py
```

该命令只读取工作区固定源码和保存证据，不更新模板。原始 Python 发射器、Unicorn 2.1.4 和 Capstone 5.0.7 的固定要求保持不变。
